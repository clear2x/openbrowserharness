# OpenBrowserHarness (openbrowserharness-extension)

English | [中文](zh/README.md)

Chrome MV3 extension host for DeepSeek Harness: the full dsh agent loop (Cordis microkernel, event-sourced sessions, tool runtime, LLM adapter) runs **entirely inside the browser**, long-lived in an Offscreen document — no Node process required.

## What this is

- **Extension-form dsh** — the same plugin packages as the Node host, booted browser-style (`new Context()` + Loader with a static module map, no yml files).
- **Long-running** — the engine lives in the Offscreen document; sessions are event-sourced into IndexedDB (`dsh-session-persistence-indexeddb`) with crash repair, and the preconfigured `main` agent carries a stable session identity, so an Offscreen recreation resumes the same conversation. A Service-Worker alarm watchdog re-creates the Offscreen host if Chrome reclaims it.
- **Browser capabilities as dsh tools** — `dsh-tool-browser` exposes `tabs_*` / `page_*` tools over the `ctx.browser` seam; the extension provider drives `chrome.debugger` (CDP) with humanized input: cubic-Bézier mouse paths, randomized keystroke timing, Shadow-DOM/iframe-piercing page snapshots.
- **Visible virtual cursor** — CDP input moves no OS pointer, so every gesture also renders an in-page overlay: a cursor arrow tracking the exact dispatched coordinates, a fading trail, and click ripples (see the [virtual-cursor Agent Note](../../.agents/notes/implemented/feature/2026-08-20-visible-virtual-cursor.md)).
- **Website tasks through real page operations** — anything done on a website — searching, opening, paging, expanding, liking, following, commenting, submitting — goes through the page the way a person works it (navigate, click, type, scroll, read what the page presents). A site's API is never requested directly — such a request trips the site's risk control and can cost the account — and a gate backs the prompt rule: a `page_evaluate` expression or a PTC `run_code` program that calls fetch/XHR or another request primitive, a `tabs_open` / `page_navigate` / `page_batch_actions` navigate step or `web_fetch` pointed at an API address, and a `video_index` index are all refused before anything runs and pointed back to the page tools, under the full-access mode as well. The built-in capability "Direct site API requests" is off by default and is turned on only when you explicitly ask for it and accept that risk (see the [decision record](../../.agents/notes/implemented/feature/2026-11-24-website-tasks-through-page-operations.md) and the [account-risk decision](../../.agents/notes/implemented/feature/2026-11-24-no-direct-site-api-requests.md)).
- **Scenario presets out of the box** — the preset switcher ships nine system-trust presets: the four native modes (Standard, PTC, Minimal, Creator) and five browser specialties (web research, page monitoring, developer probing, stock watching, the Bilibili assistant). Each follows your model route and encodes its working discipline as a prompt addendum (cross-source verification, confirmation before irreversible actions, read-only bounds). The Bilibili assistant works bilibili.com under the rule above: search, watch videos, read comments and updates, manage favorites and follows, interacting only on your explicit instruction. New sessions start in the full-access permission mode; the shield chip restores per-change or per-action approval at any time.
- **Accurate, honest operations** — clicks verify hit quality (occluded/off-viewport targets fail with a reason instead of silently clicking through), typed text is read back from the page, and a reflection guard nudges the agent when a turn ends thin or tools keep failing. Eighteen built-in capability switches (opt-in web-page screenshots, snapshot lean/masking, tracking-param cleanup, navigation settle, media blocking, submit interception, script network requests, on-demand tool groups…) tune all of it from the user-plugin panel.
- **Site learning (`/learn-site`)** — one slash command mechanically crawls the current tab's site (same-origin sub-pages, in a dedicated learning tab) and condenses it into a per-host cheat sheet — paths, forms, and stable selectors — saved as a user plugin (`site-<host>`). While that host is the active tab, the cheat sheet is injected as model context, so the agent addresses the site by known selectors instead of rediscovering them through repeated snapshots (see the [site-learn Agent Note](../../.agents/notes/implemented/feature/2026-10-08-site-learn-command.md)).
- **Video intelligence (`video_index` / `sense_now`)** — a subtitle-first long-video index: `index` pulls a Bilibili video's official/AI subtitles over allowlisted API lanes (zero-download indexing; a companion MCP server unlocks the FFmpeg/ASR-grade engine), `query` answers with cited, timestamped evidence lines (`[mm:ss–mm:ss] 台词 (EVID_x)`), and `zoom` seeks the real player and captures the frame at any timestamp (durably cited in the index's frame-evidence store) and also takes a video page URL directly, with no index and no API request. `index` requests Bilibili's API with the login state and is refused by default: it runs only while "Direct site API requests" is on. `sense_now` companion-watches the active window: bounded sampling rounds, diff-based frame keeping at three paces, and one montage sheet committed as evidence per round.
- **On-device AI (all models ≤1 GB, CPU-first)** — the「本地 AI」panel installs per-task models that run entirely inside a dedicated AI worker: PP-OCRv4 reads burned-in subtitles off captured frames (works with no GPU), SmolVLM2-256M describes frames (WebGPU), Whisper-base transcribes subtitle-less video audio into the index (`index` falls back to it automatically, ≤8-minute videos), and multilingual-e5-small powers `page_find_related` — semantic ranking of page elements by task, so large pages are addressed by relevance instead of truncated snapshots; every hit carries a unique marker selector that `page_click` / `page_type` / `page_batch_actions` can address directly, whatever attributes the page gave the element. Fetch/render compression (extractive, deterministic) trims oversized page text before it reaches the model. Every capability self-tests on install; a missing model degrades its lane honestly instead of failing the tool.
- **Local transcription paced to the machine** — Whisper transcribes in windows of about 60 seconds (each cut placed at the quietest moment, so a pause takes the cut instead of a word), and after every window the measured rate decides whether the rest still fits the budget; a machine too slow for the whole audio stops where it is and **keeps what it transcribed** instead of burning the budget for nothing. The index records how far the transcript reaches, and the `index` / `status` / `query` outputs say what was never transcribed, so the model never reads "not transcribed" as "not in the video". The「本地 AI」usage ledger records the download / decode / transcribe split of every run.
- **Batch page actions** — `page_batch_actions` runs a whole page plan (click / click_at / type / press / scroll / wait / navigate) in one call instead of several page-tool round-trips: the plan is validated before anything runs, the first failing step stops it with a per-step progress report, each click/type target is waited for and scrolled into view first, and every mutating step settles a triggered navigation before the next one runs.
- **On-demand tool groups** — the rarely used suites (team orchestration and subagents, scheduling, the file workspace, background jobs) stay out of the model's tool list until asked for: one small `load_tools` tool carries the catalog, a group becomes available for the rest of the session the moment the model loads it, and a call to a not-yet-loaded tool loads its group on the spot with a notice to call it again. Default requests roughly halve (69 → 46 tools); the「工具按需加载」capability switch restores the full list, and PTC mode composes with every tool present.
- **Self-healing debugger lane** — a debug session that dies right after attaching is retried on a backoff schedule, a command that finds the session gone re-attaches and runs once more, a discarded (sleeping) tab is reloaded before the attach, and a failure that persists names its cause: the live browser state and the most recent detach event, including the browser's「started debugging this browser — Cancel」notice being canceled.
- **Whole-replacement typing** — `page_type` into a field that already holds a value clears it before the keystrokes land, so live suggestions and validators never see the appended text the readback used to overwrite afterwards.
- **Localized shell (zh/en)** — every piece of the fork's own panel copy (composer, transcript chrome, the user-plugin / services / automation panels, the presets page, shipped preset names, on-device model labels) lives in typed dictionaries under `src/sidepanel-dsh/locales/` and rides the upstream locale service, so an English browser gets an English panel and a live language switch re-renders it. `verify-client-ui-i18n` covers `sidepanel-dsh`, so copy cannot creep back into a component. Provider display names are engine view data: the panel reports its active locale (`ui/language`) and the engine names a shipped provider in that language. Outside the panel: the toolbar title, description, right-click menu and wait notification follow the browser UI language through `public/_locales/`, and the OAuth relay page reads the browser language itself.

See the [architecture Agent Note](../../.agents/notes/implemented/architecture/2026-08-19-browser-extension-host.md) for the decision record (shim strategy, rejected alternatives).

## Layout

| Path | Role |
| --- | --- |
| `src/background/` | Service Worker: CDP controller (Bézier mouse, typed keyboard, piercing snapshot), tab ops, message router, Offscreen watchdog |
| `src/offscreen/` | Engine host: browser boot + plugin composition + auto-resume |
| `src/chrome/` | Extension-native dsh plugins: `chrome-credentials`, `chrome-llm` (DeepSeek adapter over `chrome.storage`), `chrome-browser-provider`, `ui-bridge` |
| `src/sidepanel-dsh/` | The REAL dsh web UI boot (static manifest, platform seeds, PortApiClient carrier) |
| `src/sidepanel-dsh/locales/` | The shell's zh/en dictionaries and its locale seat (`installShellLocale`); components translate through `useShellT()` / `shellT()` |
| `public/_locales/` | Manifest messages (`__MSG__`) and the strings the Service Worker reads through `chrome.i18n` |
| `src/sidepanel/` | Thin entry mounting the dsh web shell into `#root` |
| `src/shims/` | Minimal browser shims for the node: builtins the mounted closure touches (`async_hooks` ALS no-op, `crypto`, `path`, `util`, `module`, `process` globals) |
| `src/shared/protocol.ts` | Cross-context message contract (UI port, CDP channel, agent channel) |

## Build & run

```sh
# from repo root (workspace libs must be fresh)
pnpm install
pnpm run build:lib
pnpm run build:extension
```

Load `apps/extension/dist/` as an unpacked extension (`chrome://extensions` → Developer mode → Load unpacked). Click the toolbar icon to open the SidePanel, set your DeepSeek API key in settings, and talk to the agent. First automation on a tab attaches `chrome.debugger` — the browser's "started debugging" infobar is inherent to that API.

## Known Limitations and Deferred Work

- **Model/base-URL changes apply to newly created agents** — the preconfigured `main` agent captures its route at composition.
- **Node-only tool families are not mounted** (bash/fs/shell/subagent/workflow/…) — the browser closure composes the loop, todo, and browser tools only.
- **The SidePanel IS the dsh web UI** — the full client stack boots statically against the offscreen engine over a Port carrier; host-only surfaces (directory pickers, goal/preset authoring, content search) answer structured `not-available-in-extension` errors instead of rendering. Chrome ≥134 required (`using` declarations in the mounted closure).
- **The virtual-cursor overlay lives in the top frame** — gestures into same-origin iframes dispatch correctly, but the drawn cursor is the top-viewport projection.
