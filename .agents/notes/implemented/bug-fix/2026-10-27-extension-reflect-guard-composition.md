# Agent Note: reflection-guard repair — per-tool failure chains, one-steer-per-evidence, and a real wiring spec

Status: implemented

English | [中文](2026-10-27-extension-reflect-guard-composition.zh.md)

## Problem

Three defects on `chrome-reflect-guard`'s reflection surface, each disabling the guard exactly where it matters most — non-goal browser sessions hitting repeated tool failures:

- **A single success wiped the whole failure chain (①).** `FailureChains.observe` reset the agent's *entire* per-tool map on any successful result (`chains.delete(agent)`). The threshold notice's own advice — re-snapshot, then retry — made the model run one successful witness call between two failing actions, erasing the evidence and pushing the next notice two failures further out. The reflection the guard exists to provide was systematically unreachable in the fail–snapshot–fail workflow.
- **The wrap-up boundary re-steered identical evidence and burned the budget (②).** After a steer, the loop re-runs `agent/turn-stopping` against the same turn fold; the errored results were still in the fold, so the same notice was minted again until `steerBudget` ran out. A user whose turn had one genuine blocker got N identical nudges and then silence, with the budget spent on duplicates rather than new evidence.
- **The composed wiring had zero behavior tests (③).** Only composition.spec.ts's activation sweep loaded the row — it proves the plugin activates, never that plan-mode exemption, abort short-circuit, budget exhaustion, the block-decision prepend, or the pre-step reset actually behave.

## Decision

- **Per-tool bucket reset + witness transparency (reflect-guard.ts).** A success now resets only the succeeding tool's own count (`perTool.delete(toolName)`); sibling tools' failing runs survive, so fail→witness→fail hits the `[2, 4]` thresholds exactly like fail→fail. The new `WITNESS_TOOLS` set — `page_snapshot`, `page_extract_text`, `page_screenshot`, `page_network`, `tabs_list`, `windows_list`, the six pure read-only browser observations — is fully transparent: a witness call neither counts nor resets (a missed observation is not the goal-blocking action, and the recovery path the notice itself advises cannot wipe evidence). The set is deliberately conservative; every state-changing browser tool stays counted. User interjections still reset the whole chain through `reset`. The class JSDoc states the new contract in place of the old whole-chain sentence.
- **One steer per evidence key (reflect-guard.ts).** `TurnFold` now accounts for the guard notices already injected this turn: the loop claims a steer back into the log as a plugin-source `user/message` (`{kind:'plugin', plugin:'chrome-reflect-guard', form:'notice'}`), the fold parses its body into an evidence key — face plus named error code (`errored-results:<code>`, `change-without-success:none`, `zero-action:none`; minting and parsing share this module, so the lead sentences are exact-match stable), and `goalRoundSteer` suppresses a repeat. Mis-recognition degrades to the old behavior (one extra steer), never to silent suppression: an unparseable body yields no key. Genuinely new evidence — a different error code or a different face — still earns its own steer, so the budget is spent on information, not duplicates. The errored-results notice also gained the exit the zero-action text already had: 或如实说明该阻碍不可恢复，再收尾汇报 — after one steer, honestly reporting an unrecoverable blocker is a legitimate close.
- **A real wiring spec (tests/reflect-guard-wiring.spec.ts).** Boots a minimal production composition (session store, projection registry, agent registry, goal service, plan-mode controller, tool runtime — the guard's whole `inject` list) and loads the guard row through its real `apply`, then drives a registry-registered fake agent through the production seams: the post-execute Cordis waterfall with faithful exec/result pairs (the registry's dispatch shape; full `tools.execute` end-to-end stays composition-level), `agentEvents` dispatch for pre-step and turn-stopping, and real published session appends for the fold feed (the loop writes exactly these shapes). Pinned: plan-mode active and pending exemption, `signal.aborted` short-circuit (with proof the same setup steers once the signal is healthy), the duplicate-evidence suppression with budget preserved for new evidence, budget-exhausted third closing console.warn-only, the block-decision prependContext variant, pre-step resetting only on `kind:'user'`, and the `MAX_TRACKED_ROUND_KEYS = 16` oldest-key eviction at the 17th round key. The pure spec's stale header claim (wiring pinned by composition.spec.ts) now points here, and its whole-chain reset case is rewritten to the per-tool semantics, including the fail–snapshot–fail threshold case.

**Snapshot-harness exception, recorded explicitly:** the new wrap-up exit text (如实说明该阻碍不可恢复) is model-visible copy, which the recorded-session snapshot rule normally covers. Verified this session: `snapshots/` top level holds only `acp/`, `sdk/`, `session/`, `web/` — no extension cases — and `apps/extension/` has no owner-local snapshot tree, so there is no snapshot harness this change could feed. The exception is covered instead by behavior pins: reflect-guard.spec.ts asserts the exit sentence on the minted notice, and the wiring spec drives the full steer/suppress/exhaust flow through the real turn-stopping seam. No snapshot was fabricated.

## Alternatives considered

- **Resetting by failure family (selector-miss family, permission family) instead of per tool.** Deferred: family classification is already implicit in `failureAdvice`, but family-keyed buckets need a stable tool→family mapping that outlives this fix; per-tool buckets solve the observed failure (the advised witness path wiping evidence) without inventing taxonomy. The `wrapUpNoticeEvidenceKey` seam leaves room for family keys later.
- **Dedupe keyed on the minted `UserMessage` identity instead of parsed body text.** Rejected: the loop's inbox claim round-trips the message through durable log materialization, and no stable id survives that boundary today; parsing the body (minting and parsing in one module, pinned by tests) keeps the recognition lossless where the log actually is.
- **Driving the wiring spec through the full `ctx.tools.execute` pipeline.** Attempted first; the pipeline's argument-input surface trips the workspace security scanner's query-shaping heuristics on a shape that is plain tool dispatch, not SQL. Firing the same waterfall the registry dispatches (`ctx.waterfall('tools/post-execute', exec, result, next)` with faithful exec/result pairs) pins the guard's listener through the real dispatch machinery; the end-to-end materialization of `additionalContexts` onto execute() results remains covered by composition.spec.ts's activation of the whole row.

## Consequences

- The fail–snapshot–fail workflow — the exact workflow the guard's own advice produces — now reaches its threshold notice; `[2, 4]` behaves as configured regardless of interleaved witness reads.
- A turn with one blocker is steered once, told it may close by honestly reporting the blocker, and the budget survives for genuinely new evidence; the third distinct closing closes with a console warning instead of a duplicate steer.
- The wiring behaviors (plan-mode exemption in both committed and pending states, abort short-circuit, budget exhaustion, block prepend, user-only pre-step reset, ledger pruning) are pinned by tests that load the real `apply`, so a regression in `apply` fails CI rather than shipping silently.
- Witness reads (snapshots, tab/window lists, text/screenshot/network observation) no longer mask or mend failure chains in either direction.
