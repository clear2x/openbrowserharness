# Agent Note: 思考强度选择——按模型门控菜单、显式清除、持久化姿态

Status: implemented

[English](2026-09-19-reasoning-effort-selection.md) | 中文

## 问题

上一轮把思考强度控件改为常显下拉后，三个叠加缺陷让它在真机上读作「思考强度切换不了」。在 wire 行没有 reasoning 元数据的已编目模型上，每次点击级别都被静默吞掉——芯片在、点击无效、没有任何报错。固定的 关/低/中/高 菜单提供了当前模型会拒绝的档位（DeepSeek 只声明 off/low/high/max，没有 medium），点错一次后每个后续请求都以 `UNSUPPORTED_REASONING_EFFORT` 硬拒。而选中的档位只存在内存里的 per-agent 映射中，持久化的引擎设置只带 provider/model，Service Worker 重启后姿态静默回落到模型默认；乐观 UI 还用空 catch 吞掉了 RPC 失败。

## 决策

当前模型的 wire 行现在决定整个控件的形态。菜单只提供该模型声明的 `reasoning.efforts`（未映射的值原样显示；「默认/跟随模型」排在首位）；无 reasoning 元数据的已编目模型直接禁用芯片（思考：不支持），不再承载无效点击；未编目模型保留历史上的固定集合。wire 调用始终携带 `reasoningEffort`——传值即选择，`''` 即显式清除——桥把它与模型路由一起持久化为引擎级姿态（设置存储顶层），在每个既无 picked 值也无请求日志兜底的 selection 里恢复。boot 自愈会清掉目标模型拒绝的持久化档位，且目录来自同一次 `session.models` 响应而不是挂载时的过期 prop。切换失败或被拒时，乐观状态回滚，原因出现在 alert 行里。

## 备选方案

- **不支持的模型直接隐藏控件**（下拉化之前的行为）。否决：姿态是每次调用的用户控制项，隐藏读起来像功能坏了；禁用态保持可见并说明为什么不能操作。
- **用「不传 effort 字段」表示清除。** 否决：过时调用方省略字段不应抹掉已持久化的姿态；只有显式 `''` 才清除。
- **按会话持久化档位。** 否决：provider/model 路由本就引擎级持久化，姿态在会话间静默不一致会让人意外；请求发出后，每次会话的现实仍由日志头承载。

## 后果

- 面板不再可能触发运行时的 `UNSUPPORTED_REASONING_EFFORT` 拒绝：菜单只提供声明的档位，切换模型时只有目标声明支持才携带档位。
- 子代理会话经同一兜底 selection 继承引擎级姿态；单会话覆盖仍经日志头落地。
- 覆盖：composer spec 钉住禁用态、按 efforts 派生的菜单、显式清除的 wire 形状、回滚加告警路径与 boot 自愈；bridge spec 钉住持久化、清除与兜底 selection 携带姿态。
