# Agent Note: 光标 overlay 用完即隐——空闲淡出取代常驻在场

Status: implemented

[English](2026-09-19-cursor-use-and-vanish.md) | 中文

## 问题

霓虹彗星指针在契约上是永远在线的：手势结束后它在落点驻留 24 小时的在场视界，后台还有一个 4 秒一次的 keep-alive，导航后重新落位、每次心跳把它再点亮。看驱动的页面时，放大版发光指针在手势结束后还要停留几分钟，一动不动地压在与它毫无关系的内容上——用户读到的不是「agent 活着」，而是呆滞和丑。

## 决策

overlay 改为用完即隐。演出时间线是：亮着完成落点（全透明度 + 亮晕），约 4.2 秒的暗驻留（慢呼吸光晕），然后指针消散（0.6s ease-out）、动画循环排空——页面还给用户；下一次手势在路径起点淡入（0.18s 的利落过渡，消散的慢过渡不会软化再次入场）。在场机制整体删除：没有 `parkIfIdle`、没有 `touch()`、没有后台 keep-alive 定时器、没有落点簿记——每次页面调用本就幂等重装 overlay，导航后的页面不需要心跳。琥珀色活动脉冲保留为非指针操作的瞬时反应；它不再续期指针的在场，并且在没有任何位置上下文后自行抑制（没有位置的脉冲只会是视口角落的孤儿）。

## 备选方案

- **更长的驻留加手动关闭。** 否决：面板里没有合理的位置承载针对驱动页面 overlay 的关闭控件，而用户的诉求就是它别赖着。
- **保留 keep-alive 安装心跳。** 否决因为冗余：手势调用（`move`/`click`/`scroll`）与 `noteBrowserOperation` 在 overlay 缺失时本就会安装，在场结束后每标签页 4 秒一次的 evaluate 循环什么都买不到了——删掉它还顺带停掉了对每个驱动标签页的永久 RPC 滴漏。
- **从亮直接淡到消失。** 否决：暗驻留正是让观看者看清手势落在哪里的那一段。

## 后果

- 手势之间驱动的页面视觉干净：轨迹、特效与驻留视界排空后什么都不再渲染，canvas 停止占用帧。
- 手势演出本身不变（路径、彗尾、火花、冲击波、按键帽、滚动条纹）——被限定的是收尾的在场。
- 覆盖：overlay spec 钉住驻留视界的淡出分支、park/心跳 API 的不存在、每个手势入口的视界续期，以及非对称的入场/出场过渡。
