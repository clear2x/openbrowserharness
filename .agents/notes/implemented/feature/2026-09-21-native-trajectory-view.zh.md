# Agent Note：轨迹视图落地——原生历史折叠视图替代无法挂载的桌面插件路径

Status: implemented

[English](2026-09-21-native-trajectory-view.md) | 中文

## 问题

SidePanel 的 对话/轨迹 视图条从未出现：`useTrajectoryAvailable` 以 `conversation.view` 槽条目门控整个视图条，而该条目由 ui-trajectory 插件懒注入——扩展里没有任何消费者去物化桌面隐藏视图环，懒注入永不落地。修掉门控后露出更深的墙：桌面 TrajectoryView 经 `uiConversation.binding(id).target('trajectory')` 读组装账本，而账本背后的运行时会话窗口在扩展里永不物化——会话控制器的活通道（`session/control`）在扩展源上没有引擎 Remote 流（网关 WebSocket 回退无法从扩展源连接）。账本在此宿主是结构性不可挂载，与门控和顺序无关。

## 决策

SidePanel 自带原生轨迹视图，直接从 `session.history` 构建——与会话转写读取的同一份持久日志，桥上已验证可用。`buildTrajectoryRows` 按日志顺序折叠出行：轮分隔（第 N 轮）、用户提问、助手文本、工具调用（名称+参数）、工具结果（失败标红）、系统行；未知事件类型只留在对话转写中。工具栏带轮次/调用计数和大小写不敏感的文本过滤；列表跟随转写的刷新节奏（refreshSeq 触发 + 轮询）。新会话哨兵渲染明确空态且不发起任何 RPC。ui-trajectory 插件、其槽贡献、以及 shell 为其搭建的作用域管线不再位于挂载路径上。

## 考虑过的替代

- **修桌面插件路径**（物化槽条目、实现 `session/control` 流）。暂缓：活通道是线传输层的功能而非视图修复，且账本的会话窗口依赖贯穿 api-session-controller 的整个激活模型。原生视图从扩展已在服务的数据交付同样的用户可见表面。
- **保留槽条目可用性门控、只放宽它。** 否决：门控置真会挂载一个永远绑不上会话的视图——永远的 轨迹加载中。

## 后果

- 轨迹页签常驻，渲染所选会话的完整轮次时间线：计数、搜索、按轮分组的行，信息布局对齐桌面。
- 对话转写仍是完整表面（轨迹折叠有意跳过非表面簿记类型）。
- 覆盖：spec 钉住行折叠（有序 kind、失败着色、未知类型跳过）、工具栏计数、搜索过滤、哨兵空态；真机装置播种完整回合，验证视图条、空态、以及所选会话上行与工具栏的渲染。
