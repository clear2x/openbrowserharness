# Agent Note: extension wait visibility and composer command feedback

Status: implemented

English | [中文](2026-10-27-extension-wait-visibility-and-composer-feedback.zh.md)

## Problem
 Four audit findings shared one surface (extension-shell.tsx + api-bridge.ts): an approval wait silently CANCELLED itself 15s after the panel closed, so the browser automation product's core moment — waiting for a human — was destroyed by an audience that stepped away; a `/learn-site` command whose handler legitimately ran past 120s got misreported as a failure and the raw command line was fed to the model as a prompt; a first-launch panel could not open the slash menu at all (`commands/list` refused the never-materialized session); and pasting a screenshot took three manual steps.

## Decision
- **Waits carry no time bound (deliberate inversion of the fail-closed contract).** The api bridge's 15s grace window now only suppresses the false positive of a panel reload; past it nothing is cancelled. Waits end through exactly three exits: the user answers, the ask's own abort signal (turn interrupted), or plugin dispose (engine shutdown). Off-panel visibility moves to the service worker: the ask bridge feeds its live approval+question wait count to the api bridge (claim/withdraw points), the bridge computes "pending>0 AND no panel connected" at four timing points (connect, last disconnect, grace-sweep re-observation, count settlement); reporting transitions over the new `dsh-interaction-alert` channel (shared/protocol.ts) happens at all but the last disconnect — that one only arms the sweep, whose 15s re-observation reports, so a reload inside the window never flips the alert; the SW arms a toolbar badge `!` plus a persistent notification (click → `chrome.sidePanel.open`), and disarms on reconnect or drain. `teardownConnection`'s grace sweep no longer calls `cancelInteractions` — that call survives only on the plugin-disposal path.
- **Why the inversion is sound (the watchdog interaction).** While an approval is parked the engine is mid-turn (`running=true`), and the background watchdog (background/main.ts:148-170) never rebuilds a document whose engine reported running inside `ENGINE_RUNNING_GRACE_MS=180s` (main.ts:43) — so plugin dispose is NOT a de-facto time bound. When an engine genuinely dies, its waits evaporate with the offscreen document: `cancelAllPending` never runs there, so there is no leak path, only the product-intended state of "the turn is stopped, waiting for a human" (a parked turn burns no compute). The 5s `REANNOUNCE_INTERVAL_MS` re-announce keeps a reconnected panel answerable at negligible cost. The inversion holds because the recall signal — badge + notification — now exists; without it an unbounded wait would just be a silent hang.
- **Composer timeout differentiation.** `rpc-client.ts`'s local timeout refusal gains `timedOut: true` on its error (wire shape untouched); the composer's command path reports 「命令仍在后台执行，结果稍后会出现在会话中」 and does NOT re-send the line — the api bridge's `commands/execute` handler runs to settlement by design, so a re-send would double-execute and a model-feed would be worse. Genuine refusals and unknown commands keep the normal-send fallback.
- **Slash menu on first launch.** `commands/list` falls back from `session-not-found` to any live agent (the registry is global; empty when none is registered) instead of refusing, and the welcome card teaches 「输入 / 查看命令，如 /learn-site 学习当前站点」 plus the REAL shortcut pair (Enter 发送 · Shift+Enter 换行 — the old hint advertised ⌘↵ while the textarea actually sends on Enter).
- **Paste/drop intake.** `composer-attachments.tsx` exports the pure `pickImageFiles` (raster whitelist, silent drop); the shell's textarea pipes `clipboardData`/`dataTransfer` files through it into the existing `addFiles`, where the 5MB cap and wrong-type refusal notices stay single-homed. Boundary: the repo has no spec harness that mounts the shell JSX (composer-attachments.spec mounts the local hook; no extension-shell mount exists), so the paste/drop wiring is pinned only at the `pickImageFiles` unit level, not with a new shell-mount harness.

## Alternatives considered
 **A time cap on parked waits (Config field on the ask bridge).** Rejected for this batch: any cap eventually cancels a wait the user still intends to answer, and the watchdog evidence shows dispose is not a bound anyway. A future cap belongs to the ask bridge as a Config field and needs its own design pass. **Reporting the alert from the ask bridge with a push-only channel and no api-bridge registration surface.** Rejected: the api bridge owns the audience state (`connections`), so the count must cross into its closure — `setInteractionPendingListener` (consumer registration) + `notifyInteractionPendingCount` (the ask bridge's push point) is the seam that keeps both sides owning their own state. **Feeding timed-out command text to the model "so it knows".** Rejected: double execution risk and the durable `command/run`/`command/done` nodes already surface the outcome in the transcript.

## Consequences
 Closing the panel during an approval no longer kills the turn; the badge/notification recalls the user, and a reconnect (even an hour later) still answers the parked card. A timed-out long command stops masquerading as a failure and stops reaching the model. The manifest gains the `notifications` permission (permissions.md documents it as pending-confirmation-only). Existing consumers of the old fail-closed sweep: none outside the extension specs, which now pin the new semantics.
