# Agent Note: 出厂 Agent 预设——六个场景纪律，system 信任

Status: implemented

[English](2026-09-19-shipped-agent-presets.md) | 中文

## 问题

扩展的预设面早已接通——花名册 RPC、composer 切换器、按会话应用与冷恢复——但全新安装只列出隐式的 `default` 一行，没有任何可切换的东西。而这个扩展真实使用场景需要的工作纪律（研究交叉验证、购买确认闸、只读监控、填表复核）无处安放：每个会话都以同一个通用浏览 agent 启动。

## 决策

扩展出厂合并六个 system 信任预设进每份花名册，排在用户存储行之前：`web-research`（网页研究员）、`deal-hunter`（购物比价员）、`video-ops`（视频号管家）、`form-runner`（表单填写员）、`page-monitor`（页面哨兵）、`dev-probe`（页面调试手）。每个都保留完整引擎工具集并跟随当前模型路由——场景差异全部落在提示词附加段里，编码各自的工作纪律与硬性停止条件：多源交叉验证且结论附出处、任何下单/支付或对外可见内容先确认、提交前逐字段回读、监控与探查的只读边界。内置 id 拒绝 `remove`/`openDocument`，copy 也不能占用内置 id，但可以自由复制成可编辑的用户行；存储行不能遮蔽内置 id（桌面 first-root-wins）。UI 零改动——切换器渲染它本就拉取的花名册。

## 备选方案

- **安装时播种 chrome.storage。** 否决：播种的行会变成可删除的 user 信任行，以后改预设内容还要做存储迁移；源内静态行随扩展发布、随扩展更新。
- **桌面式插件组合预设**（`packages/preset/agent-presets`）。此宿主否决：MV3 没有文件系统可扫、没有动态 import，按预设挂插件行不可能；wire 词汇已用对等映射替代。
- **按预设绑定路由**（预设钉死某个 provider/model）。刻意留空：预设跟随用户配置的路由；硬依赖单一模型的场景会在路由消失时静默失效。

## 后果

- 全新花名册列出七行（default + 六个内置）；composer 切换器、`session.create { agentPreset }` 与冷恢复按现有链路直接生效。
- 场景差异按设计只落在提示词层：需要不同工具集的场景在扩展里没有机制（静态模块映射不允许按预设挂插件），本 note 记录这一边界而非未来承诺。
- 覆盖：bridge spec 钉住合并后的花名册顺序与 trust 值、内置 id 的 copy/remove 拒绝、附加段进入提示词组装（存储预设路径此前已覆盖）。
