# Agent Note：pi-ai 0.84 迁移——思考格式门禁、StopReason 扩宽、中止重映射

Status: implemented

[English](2026-09-10-pi-ai-0.84-migration.md) | 中文

## 变更内容

`@earendil-works/pi-ai` 0.82.1 → 0.84.1（Dependabot #10）扩宽了 harness 编译依赖的两个契约：

- **`PiAiThinkingFormat` 新增 `baseten`。** `catalog.ts` 的 `THINKING_FORMAT_GATE` 按设计是 `Record<PiAiThinkingFormat, true>` 漂移门禁——升级在新格式被分类前无法通过编译。`baseten` 分类为 offered（加入门禁），扩充名字分发集合。
- **`StopReason` 新增 `pending` 与 `deferred`。** `stream.ts` 的 `mapStopReason` 现在映射两者：`pending` 是 pi-ai 的 AssistantMessage 初始值，流没有产出供应方裁决时（实际场景：派发前中止）存留到终态，映射为 harness 的 `aborted`；终态出现 `deferred` 属供应方协议违例，以 `PI_AI_ERROR` 响亮失败。

## 隐蔽的一处：预中止措辞变了

0.82 中预中止请求以 `stopReason: 'aborted'` 到达 adapter；0.84 改为 `error` 事件、`errorMessage` 为调用方的中止原因（实证：`controller.abort('already stopped')` 呈现为 `{kind:'error', code:'PI_AI_ERROR'}`）——不修则调用方主动取消会被记为失败轮次。修法：`toStreamChunks` 接收调用方 `AbortSignal`，error 类 finish 与已中止信号并发时重映射为 `aborted`（`asAbortedIfCancelled`）。已完成的 `stop` finish 永不重映射——迟到的中止不得丢弃已完成的轮次。

由 `adapter.spec.ts` 既有 abort-wiring 用例覆盖（重映射前两个预中止用例失败、之后通过）及 convert 套件的 StopReason 表。
