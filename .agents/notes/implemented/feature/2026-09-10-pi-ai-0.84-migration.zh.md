# Agent Note：pi-ai 0.84 迁移——思考格式门禁、StopReason 扩宽、中止重映射

Status: implemented

[English](2026-09-10-pi-ai-0.84-migration.md) | 中文

## 问题

`@earendil-works/pi-ai` 0.82.1 → 0.84.1（Dependabot #10）扩宽了 harness 编译依赖的两个契约，并静默改变了一处行为：

- `PiAiThinkingFormat` 新增 `baseten`；`catalog.ts` 的 `THINKING_FORMAT_GATE` 是 `Record<PiAiThinkingFormat, true>` 漂移门禁，升级在新格式被分类前无法通过编译。
- `StopReason` 新增 `pending` 与 `deferred`；`stream.ts` 的 `mapStopReason` 穷举切换，同样编译失败。
- **预中止请求**——0.82 以 `stopReason: 'aborted'` 呈现——现在以 `error` 事件到达，`errorMessage` 为调用方的中止原因（实证：`controller.abort('already stopped')` 产出 `{kind:'error', code:'PI_AI_ERROR'}`）。不处理的话，harness 会把调用方主动取消的轮次记为失败。

## 决策

- `THINKING_FORMAT_GATE` 接纳 `baseten`——门禁的存在就是为了逼出这次分类，格式加入名字分发集合。
- `mapStopReason` 覆盖扩宽后的联合：`pending` 映射为 harness 的 `aborted` finish（pi-ai 以 `stopReason: 'pending'` 初始化 AssistantMessage，流没有产出供应方裁决时存留到终态——实际场景即派发前中止）；终态出现 `deferred` 属供应方协议违例，以 `PI_AI_ERROR` 响亮失败。
- `toStreamChunks` 接收调用方 `AbortSignal`；error 类 finish 与已中止信号并发时重映射为 `aborted`（`asAbortedIfCancelled`）。已完成的 `stop` finish 永不重映射——迟到的中止不得丢弃已完成的轮次。

## 备选方案

- **拒绝升级、钉在 0.82**：否决——漂移门禁在每次未来升级时都会触发，而 0.84 的契约变更很小且现在已处理。
- **通过检查中止原因文本识别取消**：否决——原因是调用方拥有的自由文本；行为应键于信号状态这一契约，而非消息措辞。

## 影响

- 被取消的请求再次报告 `aborted`，harness 的中断轮次记账与侧栏中断面在 pi-ai 0.84 上保持真实。
- `THINKING_FORMAT_GATE` 漂移门禁恢复职责：pi-ai 下一个格式新增会在分类前使编译失败。
- 由 `adapter.spec.ts` 既有 abort-wiring 用例覆盖（重映射前两个预中止用例失败、之后通过）及 convert 套件的 StopReason 表。
