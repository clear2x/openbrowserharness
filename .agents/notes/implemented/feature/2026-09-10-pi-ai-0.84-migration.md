# Agent Note: pi-ai 0.84 migration — thinking-format gate, widened StopReason, abort remap

Status: implemented

English | [中文](2026-09-10-pi-ai-0.84-migration.zh.md)

## What changed

`@earendil-works/pi-ai` 0.82.1 → 0.84.1 (Dependabot #10) widens two contracts the harness compiles against:

- **`PiAiThinkingFormat` gained `baseten`.** `THINKING_FORMAT_GATE` in `catalog.ts` is a `Record<PiAiThinkingFormat, true>` drift gate by design — the upgrade fails compilation until the new format is classified. `baseten` is offered (added to the gate), extending the name-dispatch set.
- **`StopReason` gained `pending` and `deferred`.** `mapStopReason` in `stream.ts` now maps both: `pending` is pi-ai's initial AssistantMessage value that survives to a terminal event when the stream produced no provider verdict (in practice: aborted before dispatch) and maps to the harness `aborted` finish; `deferred` on a terminal event is a provider protocol violation and fails loud as `PI_AI_ERROR`.

## The subtle one: pre-abort wording changed

In 0.82 a pre-aborted request reached the adapter as `stopReason: 'aborted'`; in 0.84 it arrives as an `error` event whose `errorMessage` is the caller's abort reason (verified empirically: `controller.abort('already stopped')` surfaced as `{kind:'error', code:'PI_AI_ERROR'}`), which the adapter would have logged as a failed turn the caller actually cancelled. Fix: `toStreamChunks` takes the caller's `AbortSignal` and an error-kind finish concurrent with an aborted signal remaps to `aborted` (`asAbortedIfCancelled`). A completed `stop` finish is never remapped — a late abort must not discard a finished turn.

Covered by the existing abort-wiring tests in `adapter.spec.ts` (both pre-abort cases failed before the remap, pass after) and the convert-suite StopReason table.
