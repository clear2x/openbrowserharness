# Agent Note: 新会话默认完全访问

Status: implemented

[English](2026-09-19-default-full-access.md) | 中文

## 问题

新会话折叠到 `ask-change`，每个变更类浏览器动作——输入、导航、开标签、脚本——都先停下来等审批。对这个扩展的核心循环（agent 代用户驱动网页）来说，开箱体验就是源源不断的审批卡，而用户明确要求默认「完全访问」。

## 决策

`DEFAULT_PERMISSION_MODE` 改为 `full`：没有 `permission/mode` 事件的会话不询问即执行，页面交互与文件变更一律如此。其余一切不变——三档矩阵、盾牌 chip 切换器、按会话的日志持久化，以及计划模式的文件写入拒绝（它与档位无关，计划获批前仍然拦截）。子代理会话共享同一折叠，所以默认同样不询问。

## 备选方案

- **做成可持久化的全局默认设置。** 否决：用户切换后档位本就按会话持久化；再加一个存储级默认会让同一姿态出现两个事实源。
- **以 `ask-always` 为默认。** 否决：最大化询问与用户的明确要求正好相反；想要的人离盾牌 chip 只有一次点击。

## 后果

- 开箱即信任 agent 执行；恢复确认只需切换器一选，对该会话持久；选中时 `ask-always`/`ask-change` 的行为与之前完全一致。
- 覆盖：gate spec 在每条 ask 路径用例上显式设置档位，并钉住无事件折叠到 `full`；bridge spec 钉住冷会话读取返回 `full`。
